Step-by-step lifecycle

0
You type a prompt in your app
Your IDE / app

You're using Cursor, VS Code, or any app that talks to an AI. You type something like "hey can u help me fix this weird openai error lol" — messy, informal, incomplete.

Normally this goes straight to OpenAI and costs tokens. With Sway, you've changed one setting: your base URL now points to localhost:8765 instead of OpenAI. That's the only change required.

1
Sway rewrites your prompt
Layer 0 · Optimizer

Before doing anything else, Sway sends your messy prompt to a cheap, fast AI (Gemini Flash) and asks it two things: what is this person actually trying to do? and rewrite this into a clear, structured prompt.

The result is a golden-form prompt — role defined, task clear, constraints explicit. This is the secret weapon: 10 different ways of asking "debug my code" all become the same clean prompt, so they can share a cached answer.

2
Sway checks if it already knows the answer
Layer 1 · Semantic Cache

Sway looks up the optimised prompt in its local memory (a tiny database on your computer). It doesn't look for an exact word-for-word match — it understands meaning. So "debug my openai call" and "fix my openai error" are recognised as the same question.

There are three checks, fastest first:

Check 1 Exact match — literally the same prompt? Return the cached answer instantly.
Check 2 Similar meaning — using AI embeddings (think: word coordinates), find prompts with the same intent. Similarity threshold: 92%.
Check 3 Judge review — a second AI call double-checks: "are these really asking the same thing?" Prevents wrong cached answers. Precision: ≥ 95%.
✓ Cache hit

The answer is already stored. Sway returns it to your app in milliseconds. No API call made. Zero tokens spent. Jump to Step 5.

✗ Cache miss

No matching answer found. Continue to Step 3 — Sway needs to ask an AI model for a fresh answer.

3
Sway picks the right model for the job
Layer 2 · Router

Not every question needs the most powerful (and expensive) AI. Sway scores the complexity of your request and picks accordingly. You opt in by using model: "sway:auto" — explicit model choices are always respected.

Nano tier · simple tasks
gpt-4o-mini · claude-haiku · gemini-flash
Short Q&A, quick explanations, simple lookups. ~10× cheaper than flagship.
Flagship tier · complex tasks
gpt-4o · claude-opus · gemini-pro
Multi-step code, architecture, large refactors. Used only when genuinely needed.

Signals Sway looks for: token count, presence of code blocks, keywords like "refactor", "architect", "debug multi-file", or "write a poem".

4
The request goes to the AI provider
Upstream API

The optimised prompt is forwarded to the chosen model — OpenAI, Anthropic, or Google. Sway streams the response back to your app in real time, so there's no extra waiting compared to a direct API call.

Behind the scenes Sway also logs the request: tokens in, tokens out, latency, which model ran, cache hit or miss. This is what powers the live dashboard.

5
Your app gets the answer
Done

The response streams back to your IDE or app exactly as if it came from OpenAI directly. From your app's perspective, nothing changed. No new SDK, no new API, no new configuration — just a different base URL.

And the next time anyone on your team asks a similar question, Sway returns the answer in milliseconds from cache — no API call, no cost, no wait.
